# 制作流程（一期像素知识口播视频，从选题到出片）

每期一个工程目录：`作品/<期号>_<书名>/`。所有时间只从配音 manifest 来，所有可复用的东西做完就进工具包。

```
作品/007_人类简史/
  00_策划.md          选题、一句话观点、贯穿隐喻、章节结构
  01_文案.md          定稿文案（纯文字，方便改）
  02_导演稿.txt       配音导演稿（导演配音.py 的输入）
  03_分镜表.md        每句一行：画面 / 运镜 / 信息呈现 / 音效 / 转场
  voice/              导演配音.py 的输出（manifest.json 是时间真相源）
  plates/             GPT 生成的背景原图（未像素化）+ 提示词 .txt
  sNN_<段名>/         每段：timeline.py / scene.py / audio.py（pixelkit 三件套）
  out/                样片、成片、混音
```

---

## 0. 策划（先定这三样，再写文案）

1. **一句话核心观点**：观众看完能复述的一句话（《人类简史》：你在为人讲出来的故事拼命）。
2. **贯穿隐喻**：一个能「玩」、能变化、结尾能回收的视觉隐喻（仓鼠轮 / 雪景球 / 关卡）。这是一期视频的美术核心。
3. **章节结构**：3 关左右，每关一个关键词（钱 / 公司 / 排名），关卡地图和顶部进度条从这里来。

## 0.5 美术圣经 + 30 秒风格样片（2026-11-09 新增，硬关卡）

001 的教训：逐句设计镜头再往上叠组件，画面元素多却不成一个世界，质感输给参考片。详见 [质感差距分析.md](质感差距分析.md)。
写分镜之前先出 `00_美术圣经.md`，一页之内写完六件事：
1. 世界外壳加 UI 词汇表（≤ 8 种）；
2. 色卡加唯一强调色的含义；
3. 每章的明暗基调；
4. 像素规格：推镜 ≤ 1.15，特写单独出图，不做模糊景深；
5. 动作主体规则：每句写「谁的手做了什么」；
6. 文字规格。

然后做一段 30 秒样片，过三关才铺全片：和参考片并排对比、`look_report.py` 达标、用户确认。

**编剧也改**：先按 [叙事方法_整合.md](叙事方法_整合.md) 第 6 节填 `00_叙事设计.md`（模板 [模板_叙事设计.md](模板_叙事设计.md)），逐句案例见 [有趣从哪来.md](有趣从哪来.md)。下面四样和美术圣经一起定：
- 题眼动作：画得出、人人做过、里面有选择；
- 情境外壳：观众在哪里、扮演谁；
- 书 → 情境的映射表；
- 道具账本：至少 3 个道具，开头埋下，结尾换一个意思拿回来。

文案改成**三栏剧本**：配音 / 画面里发生了什么 / UI 台词。三栏一起写，定稿后才配音。
每句标出它和画面的关系：L1 配图、L2 演出、L3 补刀。要求 L1 ≤ 30%，L3 每 30 秒至少一次。

## 1. 文案结构（参考片验证过的骨架，可以变，但先按它写）

| 段 | 时长 | 要做的事 | 参考《人类简史》 |
|---|---|---|---|
| 冷开场钩子 | 0–25 s | 一个寓言或反常识场景 → 三个「你」的生活排比 → 一句收束 + 大字标题 | 猴子天堂 → 纸币 / 地铁 / 加班 / 房贷 → 「为故事拼命」 |
| 背书 + 承诺 | 25–65 s | 「这句话不是我编的」→ 书 / 作者 / 销量 / 推荐 → 预判观众的怀疑 → 「那这期你更该看完」→ 收窄范围「只讲透一件事」 | 律师主持人 + 书架 + 作者卡 |
| 地图 | 3–5 s | 一共 N 关，关卡地图 | 「一共三关」 |
| 每一关 | 60–90 s | 章节卡 → 一个具体问题 → 书里的证据 / 数据 / 例子 → 反常识结论 → **拉回观众自己的生活** → 一句金句 | 第一关·钱：一百块值多少钱 → 60 万亿 / 6 万亿 → 互信系统 → 你用时间换 → 「时间是真的」 |
| 低谷 + 反转 | 20–30 s | 观众的情绪会掉（「有点丧」）→ 书真正想说的另一面 | 「故事能被人改」 |
| 方法 | 20–30 s | 一个可以马上用的方法 | 「问一句：它会不会痛」 |
| 客观 | 10–15 s | 这本书的争议 + 你自己的看法（建立可信度） | 「农业革命是骗局」有争议 |
| 收尾 | 15–25 s | 回到开场的场景 → 一个问题留给评论区 → 推荐原书 → 签名 | 凌晨改方案 → 评论区 → 买原书 → 「我们下一本书见」 |

**频道固定结尾（微光）**：
- 读书题：「……这里是微光，我陪你一本一本读下去。我们下一本书见。」
- 非读书题：「这里是微光，我们下次见。」（2026-11-09 定，首次用于 002《好看，到底值多少钱？》）

写文案时同步写「画面想法」（一句一个），不要等写完再配画面——**写不出画面的句子，往往是可以删的句子**。

## 2. 配音（先于画面）

1. 把文案按 [配音导演规范.md](配音导演规范.md) 写成 `02_导演稿.txt`（可以先让 Claude 按速查表出初版）。
2. `python 导演配音.py 02_导演稿.txt --preview` → 生成 → 听 → `--redo` 修 → 定稿。
3. 把 `输出/<稿名>/` 复制到工程的 `voice/`。从这一刻起**文案冻结**；之后再改字要重跑配音和所有时间。

## 3. 分镜表（03_分镜表.md）

每句一行，时间从 manifest 抄（或者用脚本生成表头）：

| 句 | 时间 | 文案（重读词加粗） | 画面（谁在哪、做什么） | **动作（主体 / 动词 / 道具）** | 信息呈现（手法库编号） | 运镜 | 音效落点 | 转场 |
|---|---|---|---|---|---|---|---|---|
| H01 | 0.00–3.38 | 明朝贪官杀不完，是朱元璋还不够**狠**。 | 朱元璋背影坐龙椅，案上奏折堆成山，「狠」字时拍案 | 朱元璋的手 / 拍 / 奏折 | — | 缓推 1.0→1.08 | 「狠」= 拍案 thud + 轻震屏 | — |

「动作」列每个分句都要填，UI 弹出不算动作；同一场景全片 ≤ 3 次，每次换机位。

检查：对着 [交付标准.md](交付标准.md) 第一节，每句至少一个画面节拍、最长静止 ≤ 2.5 s、每个节拍有音效落点。

## 4. 美术

两条路，可以混用，但最终都要落到**同一个像素网格**上：
- **代码画**（pixelkit sets / characters）：可复用、可动、光照正确。主角、反复出现的场景、要演戏的东西走这条。
- **GPT 生图 → `pixelkit.plates`**：一次性的大场景、复杂背景。生图后必须过 `Plate(path)`（限色 + 抖动 + 降到 320×180），角色和 UI 仍用代码画、叠在上面。
  - 提示词固定前缀（风格锁）：`pixel art, 320x180, limited palette 32 colors, HD-2D lighting, warm key light from upper left, purple shadows, no text, no UI, no characters`（角色我们自己画，背景里不要人）。
  - 每张图的提示词存成同名 `.txt` 放在 `plates/`，方便以后换风格重生。
- 第一次出现的主角 / 主持人：先出 `sheet()` 设定图确认，再进镜头。
- **GPT 还是代码：按下表决定**（用户定的原则，2026-11-08；拿不准时由主智能体判断）：

  | 画面元素 | 用什么 | 理由 |
  |---|---|---|
  | 复杂、需要精细刻画的场景（宫殿、街景、书房全景、自然风光） | **GPT 生图 → `plates`** | 细节量大，代码画性价比低 |
  | 重要的人物、反复出现 / 要做很多动作的人物（主持人、主角、贯穿全片的历史人物） | **代码画**（`pixelkit.characters`） | 要表演、要一致、要复用；GPT 拆件木偶试过，像拼贴 |
  | 一闪而过的配角、群像、远景小人 | 优先复用代码角色换装；实在没有再考虑 GPT 静态图 | 出场短，不值得建模 |
  | 简单场景（纯色房间、舞台、UI 场景）、UI、特效、数据图形 | **代码画** | 要动、要和时间轴对齐 |
  | 精细道具（古籍、印章、龙椅）| 静态的用 GPT；要动 / 要拆开的用代码或 `puppet` | |

  下面的木偶流程只在「GPT 画的道具需要有关节地动」这类少数情况下用：
- **（备用）GPT 拆件 → 代码做动画**（`pixelkit.puppet`，例子见 `templates/puppet_test/`）：
  - 提示词由主智能体写（这是美术判断），Codex 用 `gpt-6.1-sol` low **逐字照用、只生成一次**。实测这样比让 Codex 自己写提示词更快、更省额度，拆件也更好用（见 `协作/README.md`）。
  - 先出全身图（纯品红底、屏幕 / 脸留空），再以全身图为参考出拆件图：部件分开、关节端画成完整圆头、手臂画直的。
  - 表情、口型由代码画；姿势、动作全部由代码驱动（预备 → 动作 → 过冲 → 回稳、一拍二、呼吸、眨眼、天线弹簧）。
  - **混合绑骨**：GPT 只画刚性部件（头、躯干、手、道具），**四肢用代码画**、整体只描一圈外轮廓。全部用 GPT 拆件会像拼贴（用户反馈，2026-11-08）。

## 5. 动画工程（pixelkit 三件套）

每段一个目录（参考 `templates/aoye/`）：
- `timeline.py`：唯一时间源。读 `voice/manifest.json`，把每个画面节拍挂到「某句开始 / 某个重读词说出口」的时刻。
- `scene.py`：`make()` → 对象，`frame(t)` 返回 1080p 浮点 RGB，必须对 t 无状态。
- `audio.py`：人声（manifest）+ 配乐 + 音效（全部从 timeline 取时间）→ 混音 → −14 ~ −16 LUFS。

命令（Windows，已装好 `pixelkit.pth`，任何目录都能 `import pixelkit`）：
```bash
python -m pixelkit.stills s1_money/scene.py 1.0,5.5,12.0 --out _work/s1.png      # 静帧抽查
python s1_money/audio.py                                                          # 出声音
python -m pixelkit.render s1_money/scene.py:make --dur 62.5 --audio out/s1_audio.wav --out out/s1.mp4 --workers 12
python -m pixelkit.render ... --kw "{\"OW\":960,\"OH\":540}" --crf 20               # 半分辨率预览
```

## 6. 节奏：先样片，后全片

1. 每段先出**静帧拼图**（每句 1 张）→ 看构图、字、颜色。
2. 再出**前 30 秒样片**（钩子）→ 确认节奏、声音、表演都对，再做后面。
3. 全片按段渲染 → `pixelkit.assemble` 拼接（整片一个增益）。

## 7. 质检 → 发布

按 [交付标准.md](交付标准.md) 第六节跑 `qa flicker` / `vqa`，静音看一遍、只听一遍。

## 8. 沉淀（每期必做，不做不算完成）

- 新角色、新场景、新道具、新 UI 组件 → 进 `pixelkit`，`README.md` 加一行。
- 新的信息呈现手法 → [信息呈现手法库.md](信息呈现手法库.md) 加一行。
- 新音效（Freesound 下载的）→ `工具包/素材库/音效/<分类>/`，在 `音效清单.md` 记来源和许可证。
- 踩过的坑 → `pixelkit/docs/STYLE_GUIDE.md` 或本目录相应文档。
- 这一期的数据（时长、句数、语速、画面事件密度）→ `作品/<期>/复盘.md`，和参考片、上一期对比。
