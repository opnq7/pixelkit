# 配音导演规范

工具：`配音相关/导演配音/导演配音.py`（新，逐句导演）。老包 `配音相关/知识讲述配音包_v1.0/配音.py` 保留，只用来快速出整段草稿。
音色：Fish Audio「知识讲述」，模型 `s2.1-pro-free`（免费档）。

---

## 1. 老机制的问题，以及新机制改了什么

| 问题（老包 配音.py） | 后果 | 新机制（导演配音.py） |
|---|---|---|
| 一段（≤170 字）一次请求，情绪标签只能管整段 | 一段里的反讽句、结论句、设问句都是同一个语气，像「念」 | **仍然一段一次请求**（段落模式），但每句前面写自己的情绪、句中写重读——一段之内语气会变 |
| 全片统一 `atempo` 变速（示例里是 0.88 倍） | （后来实测这一步其实是**好的**，见下） | 保留：`--pace` 整体后期变速；模型的 `speed` 一律 1.00 |
| 只生成一条，好坏看运气 | Fish 同样的设置每次生成差别很大，有的条发虚 | 每段生成 3 条：先比读错率，再挑「清晰度」最高的 |
| 每段各自 `loudnorm`（LRA 11） | 段与段之间音量、压缩感不一致 | 每段先对齐到 −20 LUFS，**整条人声**再过一条轻母带链到 −16 LUFS |
| 段间固定 0.25 s 静音 | 该停的地方没停够，不该停的地方断开 | 段与段之间按设计停（句后停顿 / 段落停顿）；段内交给模型 + `[break]` |

**为什么不是「一句一次请求」（v2 试过，被否）**：每句单独生成再拼，用户实听「除了情绪，不如旧版舒服」。实测两个原因：
① 每句的起调都重新开始，相邻句子音高跳变中位 2.5 个半音（旧版 1.95）——听着像拼的；② 句间是纯数字静音（−72 dB），
旧版停顿里有自然尾音和气口（−62 dB）——一停就「断」。段落模式下这两项是 1.65～2.3 半音、−61～−65 dB，回到旧版水平。
所以：**连贯性 > 每句精确控制**。

**「闷」的真正原因（第三轮实听 + 实测，2026-11-08）**：用户说段落模式「比逐句好，但还是闷，没有旧版舒服」。
把「清晰度」（谐波噪声比 + 起音陡度，`clarity()`）量出来，排序和耳朵完全一致：段落·模型原速 1.46 < 段落·模型放慢 2.27 <
逐句 3.00 < 旧版 3.38 < 新默认 4.03。两个原因：
1. **放慢的方式**：让模型自己读慢（`speed` < 1）声音发虚、咬字变软；旧版的后期 `atempo` 拉长的主要是元音里「实」的部分，
   声音更饱满——同一条原始音频后期拉慢 0.88 倍，清晰度 2.5 → 4.2。所以**导演稿语速一栏一律 1.00，整体快慢用 `--pace`**。
2. **take 的运气**：同一段同样设置生成 3 次，清晰度 1.1 / 0.6 / 1.8。所以每段默认生成 3 条挑最清楚的。
排除掉的：情绪标签、mp3 / wav 格式（都试过，没影响）。讲故事、悲伤的段落模型本身就读得虚一点，只能靠多挑 take。`--mode line`（逐句）只在个别句子必须单独控制语速时用，而且那一句最好自成一段（前后空行）。
| 只有段落级时间 | 画面、音效、字幕高亮只能对到段落 | **逐字时间轴**（本地 whisper 回听对齐），重读词出现的时刻直接给出 `stress_at` |
| 没有质检 | 漏字、读错要靠人从头听 | 每条 take 自动回听，按拼音比对算错字率；关键句多生成一条自动挑；多音字、语速过快自动提醒 |

A/B 对比：`配音相关/导演配音/输出/AB对比/`（同一段文案，响度、时长对齐后对比，见 `说明.txt`）。

**导演稿怎么分段**：一个意思完整的段落（2–6 句、≤150 字）写在一起不空行；话题转换、要明显停一下、或者某句要单独控制时，前后空一行。
段落模式下一段只有一个语速，所以别把「快的铺垫」和「慢的金句」放在同一段——金句前空一行，单独成段。

## 2. 节奏基准（来自参考片实测）

| | 参考片（《人类简史》《富爸爸》） | 我们的目标 |
|---|---|---|
| 说话时语速 | 4.6–4.7 字/秒 | **4.3–4.8 字/秒**，单句不超过 6 字/秒 |
| 含停顿平均语速 | 4.3 字/秒 | 3.9–4.4 字/秒（5 分钟 ≈ 1200–1300 字） |
| 句间停顿中位数 | 0.30–0.36 s | 0.25–0.40 s |
| 长停顿（>0.6 s） | 每分钟 1–2 次（章节、包袱前） | 每分钟 1–3 次，**每一次都要有理由** |

参考片的问题：语速很均匀，几乎没有「快-慢」对比，听 5 分钟会有一点平。我们要的是**有起伏的匀速**：平均值相同，但铺垫句快一点、结论句慢一点、数字和金句前有停顿。

## 3. 每一类句子怎么读（导演稿速查表）

| 句子类型 | 例 | 情绪 | 语速 | 句后停顿 | 重读 |
|---|---|---|---|---|---|
| 开场钩子 / 反常识断言 | 明朝贪官杀不完，是朱元璋还不够狠。 | `sarcastic` 或 `confident` | 1.00–1.05 | 0.40–0.50（给观众一拍反应） | 句末关键词 |
| 推翻 / 反转 | 错了。 | `calm+confident` | 1.00 | 「错了。」后接 `/` | 推翻后的新论据 |
| 设问 | 那它凭什么，能换走你每天八个小时？ | `curious` | 1.00 | 0.45–0.60（问句后要等） | 问的那个点 |
| 叙述 / 铺垫 | 赫拉利在书里算过一笔账…… | `calm` 或不加 | 1.00–1.05 | 0.20–0.30 | 0–1 个 |
| 数据句 | 全世界的钱加起来，大概有**六十万亿**美元。 | `calm` | 1.00 | 0.35 | **数字本身**；数字前加 `/` |
| 举例 / 列举 | 你信，老板信，楼下卖早餐的阿姨也信。 | `relaxed` | 1.00，越往后越轻快 | 0.30 | 最后一项 |
| 共情 | 我知道这听起来有点扎心。 | `empathetic` / `soft tone` | 1.00 | 0.35 | 不重读 |
| 金句 / 结论 | 会痛的，才是真的。 | `confident` 或 `soft tone`（看情绪走向） | 1.00（单独成段，靠前后停顿给分量） | 0.70–1.00（给画面留时间） | 1 个，最多 2 个 |
| 引文 / 古文 | 田主德不我顾，呼叱昂昂。 | `calm` | 1.00 | 0.50 | 不重读；引文前用 `/`（不用 `//`） |
| 悲伤叙事 | 他的父亲，大哥，母亲，接连死去。 | `slightly sad` | 1.00 | 0.45 | 不重读、不加 `/`，逗号就够了（见下方「克制」） |
| 号召 / CTA | 你现在拼命的是哪一个故事，评论区告诉我。 | `relaxed` / `confident` | 1.00 | — | 不重读 |

**全片原则**
- 默认就是 `calm` 或不写；**每句最多 1 个情绪**（需要叠加时最多 2 个，用 `+`）；一期里情绪种类 3–5 种。
- 不用 `shouting` `screaming` `hysterical` `crying loudly`——会毁掉知识感。`laughing` `sighing` 这类声音标签一期最多 1–2 次。
- 重读一句最多 2 处，一段里不要每句都重读（全是重点等于没有重点）。
- 包袱 / 反转的前一句末尾停顿要比平常长 0.15–0.25 s。
- 数字：写成「{一九三八|1938} 年」这种形式，模型念汉字，字幕显示阿拉伯数字。
- **克制（用户实听反馈，2026-11-08）**：情绪标签、慢语速、句中停顿这三样**会叠加放大**。第一版「不到一个月……」同时用了
  `sad+soft tone` + 0.88 倍 + 三个 `/`，结果只有 3.06 字/秒，听着用力过猛。规则：
  - 负面 / 动情的情绪一律从 `slightly` 起步（`slightly sad`、`slightly worried`），不叠 `soft tone`；
  - 语速一栏一律 1.00（模型放慢会发虚，见第 1 节）；需要整体慢就 `--pace`；
  - 一句里 `/` 最多 1 个；
  - 成品每句说话速度不低于 3.6 字/秒（`report.txt` 会对太拖的句子报 ⚠）。
  悲伤、感动要靠内容和画面撑，嗓子只往下沉一点点。
- 一句话超过 30 字就拆成两行（两次请求）：一次请求越短，模型越听情绪标签的话；但也别短到 5 字以下（会丢掉语调连贯）。

## 4. 工作流

```bash
cd 配音相关/导演配音
python 导演配音.py 稿子.txt --preview      # 1. 看解析结果、预计时长、多音字提醒（不花钱）
python 导演配音.py 稿子.txt --pace 0.93    # 2. 生成：输出/稿子/voice_master.wav + manifest.json + subtitles.srt + report.txt
#    --pace：整体后期变速（0.93 ≈ 老包的成片时长；1.0 更紧凑）。每段默认 3 条 take 挑最清楚的。--mode line：逐句生成（一般别用）
#    3. 听。哪句不满意：改稿子里那一句的情绪/语速/停顿，或者直接换一条新 take：
python 导演配音.py 稿子.txt --redo S03,S07
python 导演配音.py 稿子.txt --takes 5      #    重要的片子可以每段生成 5 条挑
```

- 免费档偶尔 503：直接重跑，已完成的句子在 `cache/` 里不会重复请求。
- 输出的 `manifest.json` 是**画面时间轴的唯一来源**：每句 `start/end`、每个字的 `s/e`、重读词出现的时刻 `stress_at`。
  pixelkit 工程里用它排镜头（参考 `templates/aoye/common.py` 的 `Lines`）。
- 改了任何一句，整条的时间都会变：**画面一律从 manifest 读时间，不要手写秒数**。

## 5. 怎么让配音听起来更舒服（已经做进母带链的 + 还可以做的）

已经做了（`VOICE_CHAIN` v2）：70 Hz 低切 → 250 Hz −1.5 dB（去一点浑）→ 2.2:1 轻压缩（attack 15 ms，让辅音的起音先过去）
→ 两遍线性 loudnorm 到 −16 LUFS / −1.5 dBTP。

**少处理 = 更清脆。** 第一版链里有去齿音 + 4.2 kHz / 11 kHz 提升，用户实听「发闷、不如旧版清脆」。实测：去齿音把齿音 / 辅音的峰压平
（「齿音起伏」从 26.7 掉到 23.8 dB），高频提升只抬了稳态的气声，所以频谱更亮、听感反而更闷。Fish 这个音色本身齿音不刺，**不要加去齿音**；
要调清晰度先看「齿音起伏」和「起音陡度」两个数（`参考视频/拆解数据/脚本/` 同款测法，v2：25.8 dB / 21.5，旧版 25.7 / 16.9），不要只看频谱。

混音时还要做的（在每期的 `audio.py` 里）：
1. **配乐闪避**：说话时配乐 −15 ~ −20 dB；句间空档 > 0.5 s 时配乐抬 4–6 dB，0.15 s 内压回。
2. **一点点空间**：人声发一路很短的房间混响（预延迟 10 ms、衰减 0.4 s、湿声 −24 dB），比干声更像「在一个房间里讲」。
3. **呼吸**：句间完全的数字静音听着像拼接。停顿里铺 −50 dB 的房间底噪（`cues.room_tone`），或者保留模型生成的气口（`clean()` 已保留首尾 40–80 ms）。
4. **音效避让**：音效落在人声上时，2–5 kHz 给人声让路（音效那一轨在这个频段 −3 dB），不要让音效盖字。

还可以研究的方向（还没做）：
- 每句情绪自动建议：把文案丢给 Claude，按第 3 节的表先给一版导演稿，人再改。
- 用参考音色做「语气参考」：Fish 支持带参考音频的克隆；如果要更稳的跨句音色一致性，可以试固定 `temperature` 0.5–0.6（更稳但更平）。
- take 自动挑选目前只看错字率和语速，后续可加「音高起伏」（太平的 take 扣分）。
